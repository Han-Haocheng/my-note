### 一、FTP 的作用

FTP 的主要作用是在网络中的两台主机之间进行**可靠的文件传输**。它允许用户从远程主机下载文件到本地，或者将本地文件上传到远程主机。FTP 是应用层协议，基于 TCP 协议，因此能保证数据传输的可靠性。

### 二、FTP 的协议内容与工作原理

FTP 的工作机制有几个关键点：

1.  **双 TCP 连接**
    FTP 使用两个并行的 TCP 连接来完成工作，这是它最显著的特征：
    -   **控制连接**：用于传输控制信息（如用户名、密码、命令等）。端口号为 **21**。控制连接在整个会话期间保持打开。
    -   **数据连接**：用于实际传输文件数据。端口号通常为 **20**（主动模式）。数据连接在每次文件传输时建立，传输完成后关闭。

2.  **两种工作模式**
    -   **主动模式 (Active Mode)**：
        -   客户端从临时端口（N > 1023）连接到服务器的 21 端口，建立控制连接。
        -   客户端通过控制连接发送 `PORT` 命令，告诉服务器自己的 IP 地址和另一个临时端口（N+1）。
        -   服务器从自己的 20 端口主动连接到客户端指定的端口（N+1），建立数据连接。
        -   *问题*：客户端通常有防火墙，可能会阻止服务器主动发起的连接。
    -   **被动模式 (Passive Mode)**：
        -   客户端从临时端口（N）连接到服务器的 21 端口，建立控制连接。
        -   客户端通过控制连接发送 `PASV` 命令。
        -   服务器开启一个临时端口（P > 1023），并通过控制连接告知客户端。
        -   客户端从自己的另一个临时端口（N+1）连接到服务器的临时端口（P），建立数据连接。
        -   *优点*：所有连接都由客户端发起，更容易通过防火墙。

3.  **FTP 命令与响应**
    -   **命令**：通过控制连接以 ASCII 码形式发送。例如：
        -   `USER username`：发送用户名。
        -   `PASS password`：发送密码。
        -   `LIST`：列出目录内容。
        -   `RETR filename`：下载文件。
        -   `STOR filename`：上传文件。
    -   **响应**：服务器对每个命令返回一个三位数字的状态码和文本信息。例如：
        -   `220`：服务就绪。
        -   `331`：用户名正确，需要密码。
        -   `230`：用户登录成功。
        -   `550`：请求操作未执行（如文件不存在）。

### 三、FTP 的特点

| 优点 | 缺点 |
| :--- | :--- |
| **可靠性高**：基于 TCP，保证文件传输的完整性和顺序。 | **安全性差**：所有数据（包括用户名、密码）都以明文传输，容易被窃听。 |
| **功能完善**：支持断点续传、目录操作、文件权限管理等。 | **效率较低**：控制连接和数据连接分离，增加了复杂性。 |
| **跨平台性好**：几乎所有操作系统都支持 FTP 客户端和服务器。 | **防火墙不友好**：主动模式需要服务器主动连接客户端，容易被防火墙拦截。 |
| **支持双向传输**：既可以上传，也可以下载。 | **连接状态保持**：服务器需要维护每个用户的状态信息（如当前目录），增加了服务器负担。 |

### 四、FTP 的替代方案

由于 FTP 的安全性缺陷，现在很多场景下已经被更安全的协议取代：

-   **SFTP (SSH File Transfer Protocol)**：基于 SSH 协议，所有通信（包括认证和数据）都经过加密，安全性高。
-   **FTPS (FTP over SSL/TLS)**：在标准 FTP 协议上增加 SSL/TLS 加密层，提供加密传输。
-   **SCP (Secure Copy)**：基于 SSH 协议，用于在主机之间安全地复制文件。

**总结：** FTP 是一个经典的文件传输协议，核心在于其**双连接**和**两种模式**的设计。虽然它功能强大且可靠，但由于**明文传输**的致命缺陷，在现代网络环境中，除非在完全可信的内部网络，否则应优先考虑使用 SFTP 或 FTPS 等加密替代方案。
