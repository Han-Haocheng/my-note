
# 信号量

信号量：采用标准原语操作来解决多个相互合作的进程之间的信号同步
- 其标准原语有 wait(S) 和 signal(S) 访问，也可记为“P 操作”和“V 操作”。
- 信号量竞争：当同时修改信号量时，会发生不可避免的竞争
	- 竞争条件（Race Condition）：和调度有关的共享数据语义错误

信号：进程间通信机制中唯一的异步通信机制，可以在任何时候发送信号给某一进程，而无须知道该进程的状态


如果该进程并未处于执行状态，则该信号就由内核保存起来，直到该进程恢复执行并传递给它为止。如果一个信号被进程设置为阻塞，则该信号的传递就被延迟，直到其阻塞被取消时才被传递给进程。


来源：硬件来源，软件来源。

一旦有信号产生，系统会通过调用 kill、raise 等函数，内核来更新目的进程上下文中的某个状态，将该信号发送给目的进程，目的进程对信号的处理方式通常有三种：执行默认操作；捕捉信号；忽略信号


## 实现

### 整型信号量

整型信号量：用一个资源数目的整型量 S 表示，用原语 wait 和 signal 操作，即 PV 操作来访问。
- 引入了 P、V 操作，通过 P 操作申请进入临界区访问资源，V 操作释放资源。
- 在 wait 操作中，当信号量 S=0，wait 即进入连续测试状态
-  因此，该机制违背了“让权等待”的准则，从而使进程处于“忙等”的状态。

```c
void wait(int S){ // P操作
	while(S<=0); // 忙等
	S=S-1;
}

void signal(int S){ // V操作
	S=S+1
}
```

### 记录型信号量

记录型信号量：采用一种数据结构来记录访问资源的信息，解决整形信号量“忙等”现象。该数据结构包括一个表示资源数目的整型变量 value 和一个用于链接所有等待该资源的进程链表 L

```c
typedef struct {
    int value;
    struct process *L;
} semaphore;

void wait (semaphore S) {  //相当于申请资源
    S.value--;
    if (S.value<0) { // 资源不足
        add this process to S.L; // 将进程加入队列进行排队
        block(S.L);
    }
}

void signal (semaphore S) {  //相当于释放资源
    S.value++;
    if (S.value<=0) { // 还有进程在排队，从队列中唤醒一个进程执行
        remove a process P from S.L;
        wakeup(P);
    }
}
```


## 应用

### 实现进程同步

信号量实现进程同步：假没进程 `P1` 和 `P2` 并发执行。其中 `P0` 中有一条语句 `S0` ，`P1` 中有一条语句 `S1` ，要求 `S0` 必须在 `S1` 之前执行。为了实现同步，在实现箅法中增加一变量 `S` ，表示进程 `P0` 、 `P1` 同步的公共信号量，初值为 `0`

```c
semap S =0;
void P0(){
	// ...
	S0;
	V(S); 
}

void P1(){
	//...
	P(S); // 
	S1;
}
```

### 实现进程互斥

假设有进程 `P1` 和 `P2` 并发执行，两者有各自的临界区，但系统要求每次只能有一个进程进入自己的临界区。因此，采用信号量实现互斥、设置一个表示可虍资源数信号初值为 1 （因为只有一个资源），要实现两进程的互斥进入临界区，只需要将临界区放在 `P(N)` 和 `V(N)` 之间即可

```c
semaphore S=1;  //定义表示可用资源数的信号量,并初始化
P1(){
    //...
    P(S);        //准备申请访问临界资源,加锁
    //进程 P1 的临界区
    V(S);        //访问结束,释放资源,解锁
    //...
}
P2(){
    //...
    P(S);        //准备申请访问临界资源,加锁
    //进程 P2 的临界区
    V(S);        //访问结束,释放资源,解锁
    //...
}
```
