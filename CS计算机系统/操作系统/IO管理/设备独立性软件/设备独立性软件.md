# 设备独立性软件

**设备独立性软件**：实现用户程序与设备驱动器的统一接口、设备命名、设备保护以及设备的分配与释放
- **设备独立性**（设备无关性）：应用程序独立于具体的物理设备
- 执行所有设备的公有操作，向用户层提供统一接口

## 设备

访问 I/O 设备时，必须将逻辑地址转换为物理地址
### 逻辑设备

**逻辑设备**：应用程序中定义，用于请求某种设备，增加分配灵活性

逻辑设备表LUT：表项包括逻辑设备名、物理设备名和设备驱动程序入口地址，应用程序通过逻辑设备名访问 I/O 设备，无需使用物理名，通过 LUT 找到对应物理设备和驱动程序入口地址

建立方式
- 整个系统设置一张 LUT：所有逻辑设备名不允许重名，适用于单用户系统
- 每个用户设置一张 LUT：用户登录时建立，放入进程的 PCB 中

### 物理设备

**物理设备**：系统实际执行时使用的设备

### 设备分配与回收

数据结构
- **系统设备表SDT**：系统范围的数据结构，记录已连接到系统中的所有物理设备，每个设备分配一个表目
	- 包括设备类型、设备标识符、设备控制表及设备驱动程序入口等字段
- [[设备控制表]]
- **控制器控制表COCT**：系统为每一个控制器配置一张控制器控制表，反映设备控制器的使用状态及与通道的连接情况
- **通道控制表CHCT**：每个通道配有一张通道控制表记录通道的情况

设备属性
- **独占性设备**：采用独享分配策略。将设备分配给某进程后由该进程独占，直至该进程完成或释放后才能再分配给其他进程
	- 不足：设备利用率低，可能引起死锁
- **共享性设备**：允许被同时分配给多个进程使用。须注意对访问该设备的先后次序进行合理调度
- **可虚拟设备**：一台物理设备采用虚拟技术后可变为多台逻辑上的虚拟设备，可虚拟设备是可共享的设备，可同时分配给多个进程使用

分配算法
- **先来先服务FCFS**：根据多个进程请求设备的时间先后顺序构成队列，设备分配程序总是把设备优先分配给队首进程
- **优先级高者优先**：根据进程优先级的高低进行设备分配，若优先级相同，则依据先来先服务算法进行分配


安全性
- **安全分配方式**：进程发出 I/O 请求后立即进入阻塞状态，直至 I/O 操作完成时才被唤醒，进程获得设备后进入阻塞态，不再请求其他资源，摒弃了死锁必要条件之一的“请求和保持”条件，处于安全状态
	- 不足：CPU 与 I/O 设备串行工作，进程执行缓慢
- **不安全分配方式**：允许进程在发出 I/O 请求后继续运行，并可继续发出多个 I/O 请求，直到所请求的设备被另一进程占用时才进入阻塞态
	- 优点：一个进程可同时操作多个设备，执行速度快
	- 缺点：多个进程请求设备可能引起资源分配不均而产生死锁


流程：分配设备 → 分配控制器 → 分配通道
1. **分配设备**：根据 I/O 请求中的物理设备名查找[[系统设备表]]，找到该设备的 [[设备控制表|DCT]]
	- 若设备空闲，将请求的 PCB 插入设备等待队列
	- 否则挂在设备队列上
2. **分配控制器**：在 [[设备控制表|DCT]] 中查找与该设备连接的控制器的 [[控制器控制表|COCT]]
	- 若控制器忙，将进程 PCB 挂在控制器等待队列上
	- 否则分配给进程
3. **分配通道**：在 [[控制器控制表|COCT]] 中找到与该控制器连接的通道的 [[通道控制表|CHCT]]
	- 若通道忙，将进程 PCB 挂到通道等待队列上
	- 否则分配给进程

### SPOOLing 技术


**SPOOLing 技术**：利用多道程序技术，用一道程序模拟脱机输入时的外围控制机功能，把低速 I/O 设备上的数据传送到高速磁盘上，再用另一道程序模拟脱机输出时外围控制机的功能，实现在主机直接控制下的脱机输入、输出功能

虚拟性
- 多道程序技术可将一台物理 CPU 虚拟为多台逻辑 CPU
- SPOOLing 技术可将一台物理 I/O 设备虚拟为多台逻辑 I/O 设备
- 将独占设备虚拟为若干个共享设备

作用
- 外围操作与 CPU 对数据的处理同时进行
- 缓解 CPU 高速性与 I/O 设备低速性间的矛盾

特点
- 提高了 I/O 的速度：将对低速 I/O 设备的操作变为对输入井或输出井的操作，缓解了 CPU 与低速 I/O 设备之间速度不匹配的矛盾
- 将独占设备改造为共享设备：并未为任何进程分配设备，只在输入井或输出井中为进程分配存储区和建立 I/O 请求表
- 实现了虚拟设备功能：
	- 宏观上：多个进程在同时使用一台独占设备
	- 微观上：每个进程独占的设备实际上只是逻辑上的设备

组成

在磁盘上开辟两个存储区域
- 输入井：模拟脱机输入时的磁盘设备，暂存 I/O 设备输入的数据
- 输出井：模拟脱机输出时的磁盘设备，暂存用户程序的输出数据

在内存中开辟两个缓冲区
- 输入缓冲区：暂存由输入设备送来的数据，再传送到输入井
- 输出缓冲区：暂存从输出井送来的数据，再传送给输出设备

模拟脱机 I/O 时的外围控制机
- 输入进程 SPi：将数据从输入机通过输入缓冲区送到输入井，CPU 从输入井读入内存
- 和输出进程 SPo：将数据从内存送到输出井，待输出设备空闲时经输出缓冲区送出


实例

打印机是独占性设备：通过 SPOOLing 变成可供多个用户共享的设备，提高设备利用率

共享打印过程
- 输出进程在输出井中申请空闲磁盘块区，将要打印的数据送入其中
- 输出进程为用户申请空白请求打印表，填入打印要求，挂到请求打印队列
- 打印机空闲时，从队首取出请求打印表，从输出井传数据到缓冲区再打印
- 打印完后检查队列，若有等待请求则继续，直至队列为空则自我阻塞
