### 设备分配回收

数据结构
- **系统设备表SDT**：系统范围的数据结构，记录已连接到系统中的所有物理设备，每个设备分配一个表目
	- 包括设备类型、设备标识符、设备控制表及设备驱动程序入口等字段
- [[设备控制表]]
- **控制器控制表COCT**：系统为每一个控制器配置一张控制器控制表，反映设备控制器的使用状态及与通道的连接情况
- **通道控制表CHCT**：每个通道配有一张通道控制表记录通道的情况

设备属性
- **独占性设备**：采用独享分配策略。将设备分配给某进程后由该进程独占，直至该进程完成或释放后才能再分配给其他进程
	- 不足：设备利用率低，可能引起死锁
- **共享性设备**：允许被同时分配给多个进程使用。须注意对访问该设备的先后次序进行合理调度
- **可虚拟设备**：一台物理设备采用虚拟技术后可变为多台逻辑上的虚拟设备，可虚拟设备是可共享的设备，可同时分配给多个进程使用

分配算法
- **先来先服务FCFS**：根据多个进程请求设备的时间先后顺序构成队列，设备分配程序总是把设备优先分配给队首进程
- **优先级高者优先**：根据进程优先级的高低进行设备分配，若优先级相同，则依据先来先服务算法进行分配


安全性
- **安全分配方式**：进程发出 I/O 请求后立即进入阻塞状态，直至 I/O 操作完成时才被唤醒，进程获得设备后进入阻塞态，不再请求其他资源，摒弃了死锁必要条件之一的“请求和保持”条件，处于安全状态
	- 不足：CPU 与 I/O 设备串行工作，进程执行缓慢
- **不安全分配方式**：允许进程在发出 I/O 请求后继续运行，并可继续发出多个 I/O 请求，直到所请求的设备被另一进程占用时才进入阻塞态
	- 优点：一个进程可同时操作多个设备，执行速度快
	- 缺点：多个进程请求设备可能引起资源分配不均而产生死锁


流程：分配设备 → 分配控制器 → 分配通道
1. **分配设备**：根据 I/O 请求中的物理设备名查找[[系统设备表]]，找到该设备的 [[设备控制表|DCT]]
	- 若设备空闲，将请求的 PCB 插入设备等待队列
	- 否则挂在设备队列上
2. **分配控制器**：在 [[设备控制表|DCT]] 中查找与该设备连接的控制器的 [[控制器控制表|COCT]]
	- 若控制器忙，将进程 PCB 挂在控制器等待队列上
	- 否则分配给进程
3. **分配通道**：在 [[控制器控制表|COCT]] 中找到与该控制器连接的通道的 [[通道控制表|CHCT]]
	- 若通道忙，将进程 PCB 挂到通道等待队列上
	- 否则分配给进程
