# 用户数据报协议



### UDP

 用户数据报协议 UDP(User Datagram Protocol)：


用户数据报协议 UDP(User Datagram Protocol)：基于Internet IP协议实现复用/分用功能和简单的错误校验功能。提供Best effort服务，数据会丢失或乱序。是一个无连接协议，—提供无连接的、尽最大努力 (best-effort)的数据传输服务（不保证数据传输的可靠性）

- 无连接：连接双方不需要握手，各段独立处理
- 传输单元：用户数据报 User Datagram

- 相关[[应用层]]协议：DNS. [[DHCP 动态主机配置协议|DHCP]]、[[RIP路由信息协议|RIP]]、流媒体应用、SNMP
- 在应用层增加可靠性机制

## 特点
特点：无连接、实现简单、头部开销小、没有拥塞控制、支持多种交互通信、尽最大努力交付
- *无连接*：减少延迟，发送数据前不需要建立连接，发送结束后也没有连接释放,减少了开销和发送时延
- *实现简单*：无须维护连接状态
- *没有拥塞控制*：网络出现拥塞不会使源主机的发送速率降低，应用可更好的控制发送时间和速率
- *支持多种交互通信*：支持一对一、一对多(广播)、多对一和多对多的交互通信。
- *尽最大努力交付*：即不可靠传输。UDP 不保证可靠交付,不使用流量控制和拥塞控制。如果数据包在传输中丢失或出错,UDP 协议本身不负责重传。
- *面向报文*：发送方 UDP 对应用层交下来的报文,既不合并,也不拆分,而是保留这些报文的边界。

### 校验和

UDP校验和：检测UDP段在传输中是否发生错误

- 发送方：将内容(伪首部、首部、数据)视为16bits整数组，数组求和，进位加1，按位求反，
- 接收方：按照发送方式计算，对比校验和，检测有限错误


校验和的计算方法，以 n 个字节的数据为例：
1. *判断奇偶*：检查 n 是奇数还是偶数，如果是奇数的话，在所有数据的最后再添加 1 个字节的数据，这个字节的数据全设为 0；
2. *2 字节切块*：按顺序将数据划分为 16 位的字节块，也就是让每个字节块占两个字节；
3. *块求和*：对多个字节块执行二进制加法操作，注意，这里是二进制加法，而不是异或，是需要有进位的。通过加法操作，得到数 X；
4. 溢出加到低位：如果 X 的值超过 16 位的话，将高位溢出的部分回回到低位；
5. 将 X 的值按位取反，最后得到的数据便是校验和。
